## 0. 목적과 실행 원칙

WashHub는 공개 출시 후 신규 사용자가 확인되지 않아 서비스를 종료한다. 이 문서는 App Store, Supabase, OAuth, 웹 문서 및 소스 아카이브를 **복구 가능성을 보존하면서** 정리하기 위한 운영 절차다.

- App Store에서 앱을 내리는 일과 Supabase를 끄는 일은 별도 작업이다. 설치된 앱이 남아 있을 수 있으므로 순서를 바꾸지 않는다.
- **기존 설치자 고지가 최우선 게이트다.** 백엔드 종료·데이터 파기는 종료일, 데이터 처리, 문의 경로를 설치자에게 알릴 수 있는 수단을 확보하고 공지한 뒤에만 진행한다.
- 사용자·콘텐츠가 실제로 0건인지 확인하기 전에는 Auth, Database, Storage를 삭제하지 않는다.
- 서비스 종료에 필요한 정보만 별도 보관하고, 개인 식별 정보와 사용자 콘텐츠는 법적 보존 근거가 없으면 파기한다.
- 본 문서는 운영 절차다. 개인정보 보유·파기 기간과 공지 의무는 적용 국가 및 실제 데이터에 따라 개인정보 전문가의 최종 검토를 받는다.

## 2. 단계별 체크리스트

### Phase A — 종료 전 스냅샷 (T0)

아래 항목은 **삭제 또는 비활성화 전에** 완료한다.

- [ ] App Store Connect → App Analytics에서 설치, 활성 기기, 세션, 크래시, 평점·리뷰를 PDF 또는 이미지로 보관
- [ ] App Store Connect → Sales and Trends에서 다운로드·수익·구독·환불이 모두 0인지 확인
- [ ] App Store Connect → TestFlight에서 진행 중인 테스트·빌드가 없는지 확인
- [x] Supabase Dashboard → Authentication 사용자 목록 확인 — 총 18개 계정 존재. 계정의 테스트/실사용 구분과 연결 데이터 확인은 미완료
- [ ] Supabase Database에서 공개 테이블별 행 수와 최근 `created_at`을 CSV/스크린샷으로 보관
- [ ] Supabase Storage에서 `feeds`, `profiles` 등 사용자 파일 버킷의 파일 수·용량 확인
- [ ] Supabase Logs에서 최근 30일 오류, `withdraw-user`, 인증, Storage 오류 확인
- [ ] GitHub Pages의 개인정보처리방침·이용약관·문의 URL이 정상 노출되는지 확인
- [ ] 운영 계정·권한 목록 작성: Apple Developer, App Store Connect, Supabase, GitHub, 도메인, 이메일, APNs, Google OAuth
- [ ] DB와 Storage를 암호화된 내보내기 파일로 백업하고, 복구 가능 여부를 확인

**통과 기준:** 외부 사용자 데이터가 0건인지, 남은 데이터의 소유자·목적·파기 방식을 설명할 수 있다.

### Phase B — 기존 설치자 공지 준비 및 발송 (T0~T1)

WashHub `1.1.2`에는 서버 공지·원격 설정을 조회하는 구현이 없다. 단순히 Supabase에 공지 테이블을 추가해도 이미 설치된 `1.1.2`에는 표시되지 않는다. 다음 중 최소 한 가지를 실제로 실행하고 증적을 남긴다.

- [x] 종료 안내 업데이트 구현 — 앱 시작 시 종료일·데이터 처리·문의처를 전체 화면으로 표시하는 `1.1.3` (build 2) 작성 완료
- [ ] `1.1.3` App Store 버전 생성, build 2 연결, 심사 제출 및 기존 설치자 배포 — build 2는 TestFlight에서 “제출 준비 완료”; 대한민국 판매 재개 반영 대기
- [ ] 푸시 알림 — 실제로 등록된 푸시 토큰과 동의가 있는 경우에만 종료 공지 발송
- [ ] 이메일 — 개인정보처리방침의 운영 목적과 수신 거부 여부를 확인한 뒤, 기존 계정의 이메일에 종료 공지 발송
- [ ] 지원/마케팅 URL, GitHub Pages, 공식 SNS에 동일한 종료 공지 게시
- [ ] 공지 채널별 발송·게시 시각과 수신 범위를 종료 기록에 보관

**통과 기준:** 기존 설치자가 앱 또는 외부 공식 채널을 통해 종료일, 데이터 처리 방법, 문의처를 확인할 수 있다.

### Phase C — 신규 유입 중단 (T1~T2)

- [x] App Store Connect → **Pricing and Availability**에서 신규 다운로드 중단 요청 후, 공지 업데이트 배포를 위해 대한민국만 판매 재개 설정 — 2026-10-10, 반영 대기(Apple 안내: 최대 24시간)
- [ ] 앱이 App Bundle 또는 In-App Purchase에 연결돼 있다면 해당 판매 상태도 확인
- [ ] 앱 레코드 삭제는 하지 않음 — 앱 이름, SKU, Bundle ID 재사용 제약 때문에 종료 증적·복구 판단이 끝난 뒤 최종 결정
- [ ] 새 TestFlight 초대와 새 배포를 중지
- [ ] 외부 링크·SNS·소개 페이지에서 설치 유도 문구를 제거하거나 “서비스 종료 예정”으로 변경

**금지:** 이 단계에서 Supabase 프로젝트, Edge Function, Apple/Google OAuth를 끄지 않는다. 기존 설치자가 앱을 열거나 계정 삭제를 요청할 수 있다.

### Phase D — 사용자 보호 기간 (T2~T3)

- [ ] 외부 사용자가 존재하면 앱 내 공지, GitHub Pages, 문의 이메일로 종료일·데이터 처리·문의처를 고지
- [ ] 공지에는 신규 가입·새 콘텐츠 작성 중단일, 최종 종료일, 데이터 삭제 요청 방법, 문의 기한을 포함
- [ ] 기존 설치자가 있을 수 있으면 계정 삭제와 개인정보 문의 경로를 유지
- [ ] 읽기 전용 전환이 필요하면 신규 가입·피드/댓글/리뷰/이미지 업로드만 막고, 데이터 조회·삭제 요청은 유지
- [ ] 문의 이메일의 자동 회신에 종료일과 처리 기한을 명시
- [ ] 종료 기간의 신고·개인정보 요청·오류 문의를 기록하고 답변

**WashHub 현재 정책 점검:** 개인 식별 정보를 익명화하고 UGC를 보존하도록 되어 있다. 서비스 종료 시에는 이 정책을 자동 적용하지 않는다. 실제 사용자 데이터가 있으면 보존할 항목·법적 근거·기간을 별도로 확정하고, 근거가 없는 개인 데이터와 콘텐츠는 파기한다.

### Phase E — 최종 종료 (T3)

- [ ] T1 이후 새 가입, 새 콘텐츠, 개인정보 요청이 없는지 재확인
- [ ] 개인정보처리방침과 이용약관에 서비스 종료일 및 종료 후 문의 경로를 반영
- [ ] App Store에 앱이 신규 다운로드 불가 상태인지 재확인
- [ ] Apple/Google 로그인, Supabase Database/Storage/Auth/Edge Function을 **아래 순서대로** 종료
  1. 사용자 데이터 삭제·내보내기 요청 마감
  2. Auth 사용자 및 식별 가능한 프로필 데이터 파기
  3. Storage 사용자 이미지·첨부 파일 파기
  4. Database 사용자 콘텐츠·검색 이력·알림·로그 파기 또는 법적 근거가 있는 최소 데이터만 분리 보관
  5. Edge Functions 비활성화 및 Secrets 폐기
  6. OAuth Redirect URL·client secret·APNs 키 폐기
  7. Supabase 프로젝트의 과금·백업·접근 권한 종료
- [ ] GitHub Pages에는 서비스 종료 안내와 개인정보 문의 방법만 유지

### Phase F — 사후 정리 (T3 이후)

- [ ] 종료 완료일, 파기 범위, 보관 데이터, 보관 종료일을 내부 종료 기록에 남김
- [ ] 개인정보 문의 이메일을 정한 기간 동안 모니터링
- [ ] Apple Developer 및 Supabase의 청구·자동 갱신이 없는지 확인
- [ ] GitHub 저장소를 private archive로 보관하고 Secrets가 커밋 이력에 없는지 재점검
- [ ] 개인정보 문의 기간 종료 후, 별도 보관한 백업과 종료 증적의 접근 권한을 최소화 또는 파기
- [ ] App Store 앱 레코드 삭제 여부를 마지막으로 결정

## 3. 데이터 인벤토리와 처리 결정표

| 자산 | 종료 전 확인 | 종료 시 기본 처리 | 예외 / 증적 |

| Storage `feeds`, `profiles` | 객체 수·용량·공개 URL | 사용자 파일 파기 | 백업에도 동일 보존 기한 적용 |
| Edge Functions/Secrets | 배포 목록·호출 로그 | 함수 비활성화, Secrets 폐기 | 키 폐기 전 앱 동작 중단 확인 |

| 소스·마이그레이션 | 저장소·라이선스·Secrets | private archive | 개인정보·운영 키 제외 |

## 4. 종료 공지 초안

### 앱/웹 공지

```text
[WashHub 서비스 종료 안내]

WashHub 서비스는 YYYY년 MM월 DD일(KST)을 끝으로 종료됩니다.

- 신규 가입 및 콘텐츠 작성 종료: YYYY년 MM월 DD일
- 서비스 최종 종료: YYYY년 MM월 DD일
- 개인정보 및 계정 관련 문의: [문의 이메일]
- 문의 접수 마감: YYYY년 MM월 DD일

서비스 종료 후에는 앱 이용과 데이터 조회가 불가능합니다.
보유 정보는 개인정보처리방침 및 관련 법령에 따라 파기하거나, 법적 보존 의무가 있는 최소 항목만 분리 보관합니다.

그동안 WashHub를 이용해 주셔서 감사합니다.
```

### 문의 자동 회신

```text
문의가 접수되었습니다. WashHub는 YYYY년 MM월 DD일(KST)에 서비스를 종료합니다.
개인정보 열람·정정·삭제 요청은 본 메일에 필요한 내용을 회신해 주시면 확인 후 안내드리겠습니다.
```

- [ ] 실제 사용자·콘텐츠·결제·개인정보 요청 수를 증적으로 확인했다.
- [ ] 필요한 종료 공지와 개인정보 문의 경로를 유지했다.
- [ ] 개인정보와 Storage 파일의 파기 또는 법적 분리 보관을 완료했다.
- [ ] Supabase, OAuth, APNs, Edge Function Secrets와 과금이 종료됐다.
- [ ] 소스와 비개인 운영 기록만 private archive에 보관했다.
- [ ] 종료 책임자와 완료일이 기록됐다.
